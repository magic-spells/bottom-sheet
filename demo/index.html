@magic-spells/bottom-sheet

A sheet with momentum.

A small custom element for grounded, accessible dialogs—dragged by pointer, aware of scroll, and polished for the edges of a touch screen.

Install npm i @magic-spells/bottom-sheet @magic-spells/dialog-panel
01 · anatomy

Begin with three quiet layers.

A parent panel owns modal behavior, the native dialog supplies the boundary, and the sheet divides itself into a draggable header and scrollable content. 

<dialog-panel>
  <dialog>
    <bottom-sheet>
      <bottom-sheet-header>…</bottom-sheet-header>
      <bottom-sheet-content>…</bottom-sheet-content>
    </bottom-sheet>
  </dialog>
</dialog-panel>
02 · velocity

Let the release decide.

Drag down and release. The sheet dismisses when velocity is greater than 0.5 px/ms, or after more than 100px without an upward reversal. The local readout mirrors those rules at release.

Waiting for a release… 
// Either path dismisses
velocityY > 0.5
deltaY > 100 && velocityY > -0.05
03 · scroll

Content keeps the gesture it needs.

The list scrolls naturally. Only a downward drag that begins while the content is at the top transfers control to the panel; every other gesture remains ordinary scrolling. 

// Policy inside BottomSheet
isAtTop && direction === 'down'
  ? claimPanelDrag()
  : allowNativeScroll()
04 · morph

A card can become the sheet.

Assign a morph engine to the parent panel and pass the card as the trigger. Gesture policy stays out of the way while the opening or closing flight is active. 

const panel = document.querySelector('#morph-panel')
panel.morphEngine = new MorphEngine.MorphEngine({
  lockScroll: false,
  zIndex: 10000000,
})
card.addEventListener('click', () => panel.show(card))
05 · responsive

Give the sheet a horizon.

This example uses max-display-width="768". Open it below that width, then resize beyond the boundary and the sheet closes itself. 

<bottom-sheet
  max-display-width="768">
  …
</bottom-sheet>
06 · lifecycle

Every state leaves a trace.

The parent panel emits beforeShow, shown, beforeHide, and hidden. Open the sheet, close it, and watch each event arrive with detail.state. 

No events yet.
panel.addEventListener('shown', (event) => {
  console.log(event.detail.state)
})
07 · reference

The whole surface, in one place.

Three elements, one responsive attribute, eleven style tokens, two methods, and the parent panel’s four lifecycle events. The live trigger uses the same canonical anatomy. 

const sheet = document.querySelector('bottom-sheet')
sheet.show(trigger)
sheet.hide()

Accessibility

Modal semantics, focus trapping, focus return, and Escape handling are delegated to the parent panel and its native <dialog>. Close controls use the parent’s data-action-hide-dialog action.

Browser support

Modern browsers with custom elements, native dialog, Pointer Events, and :has().

Field notes, expanded

The source card remains the visual origin. Once the flight settles, this is the same bottom sheet—with the same gestures and modal behavior.

Only under 768px

Resize the viewport beyond 768px. The component notices the boundary and delegates closing to its parent panel.

Lifecycle in motion

Close this sheet to complete the event sequence, then inspect the log in the section.

Small by design

The public API stays deliberately narrow. Compose the sheet with ordinary HTML, style it through custom properties, and listen on the parent panel.
